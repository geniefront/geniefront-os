## 2. 审查记录和关闭规则

每项保留：基线/工作树、业务不变量、真实入口、主体及权限、前置状态、操作序列、预期与实际、证据文件、影响范围、修复范围、剩余条件。

证据分开标记，不用总分掩盖缺口：

| 标记 | 能证明什么 | 不能证明什么 |
|---|---|---|
| S 源码 | 某基线的控制流、契约、配置 | 数据库实际权限、线上行为 |
| L 本地定向执行 | 被执行函数/脚本在指定输入下的行为 | 未执行的真实依赖；替身不得计为真实 PG |
| D 真实隔离 DB/HTTP | 实际事务、约束、受限身份、HTTP 结果 | 生产配置和真实外部送达 |
| B 浏览器 | 页面入口、会话、交互、离线及视觉表现 | 服务端未覆盖状态和供应商事实 |
| X 外部验证 | 明确环境中供应商接受/失败/查询的实际事实 | 其他环境、未发生的恢复窗口 |

状态采用：待验证、历史确认待复核、已复现、部分修复、已验证关闭、不适用。源码出现 guard 只算修复线索；关键正向、否定与恢复用例通过后才关闭。一次正常收款成功不能代替重试、响应丢失和重启恢复。

优先级：P0 用于已证实且需立即处置的重大问题（当前无此结论）；P1 为关键资金、敏感授权或环境目标保护；P2 为重要功能/交付可靠性。待验证项目不预先赋予缺陷等级；下文“先后顺序”是审查安排。

## 3. 原有 9 项逐项展开

以下统一为“历史确认待复核”；位置链接及原始行号见原报告，历史证据不是本次运行结果。

### P1-01 改价越权

- 入口：`ticket.open`、`ticket.addItem`；检查 routes → 命令授权 → handler → 金额落库全链。
- 不变量：具备开单权限不自动具备改价权限；实际价格变化须由有权主体授权。
- 历史证据 D：默认技师 `ticket.discount=false`，4500 分项目覆盖为 0，HTTP 201，subtotal 为 0，见 `AUDIT_PRICE_OVERRIDE`。目前证据直接覆盖开单；加项路径为源码判断。
- 补验：开单与加项各测覆盖为 0、低于原价、高于原价、等于原价、负数；再测合法经理、无效服务、跨店服务、套餐及重复 key。等价覆盖按明确政策处理。
- 修复边界：授权应在服务端统一执行；不可只禁用输入框或仅在结账检查。金额变化审计需保留操作者、旧值、新值、理由。
- 关闭：无权实际改价被拒且工单/行项/审计成功记录不发生写入；有权改价正常；重放不重复计价，正常目录价开单不回归。

### P1-02 技师读取全店他人订单

- 入口：`GET /v1/desk/orders`、订单详情及相关导出/小票/客户历史入口。
- 不变量：租户隔离与同店角色范围分别成立；客户端 staffId 不能决定服务端授权范围。
- 历史证据 D：50 条中 39 条不属于该技师，且含金额，见 `AUDIT_ORDERS`。这是同店越权，不是跨租户泄露。
- 补验：不传 staffId、传本人/他人/跨店 ID；分页、搜索、统计聚合；参与多人订单时字段范围；前台与店主正向读取。
- 修复边界：查询条件与字段投影共同限定；不能只过滤列表而保留详情或聚合旁路。多人订单“可看整单还是只看本人项目”需落实到明确产品规则。
- 关闭：所有适用读取入口执行相同范围规则；技师不能从总数/汇总/导出绕过；合法员工仍可完成本人业务。

### P1-03 官网抓取 DNS 重绑定

- 入口：官网导入的 URL 验证、实际连接和重定向。
- 历史证据 L：校验公网解析后，连接到本机服务一次，内容被返回，见 `dns_rebinding`；未连接真实内网资产。
- 补验：IPv4/IPv6 私网与回环、混合解析结果、重定向至禁用地址、每次连接重新解析、超时、超大分块响应、压缩后超限。
- 修复边界：校验绑定实际连接地址并保留 Host/SNI；每跳重新执行策略。另设流式字节与总时长上限，读取后截断不能控制峰值内存。
- 关闭：受控反例内部命中数为 0；允许公网目标仍可导入；所有重定向及重试保持策略；超限中止并释放连接。大响应风险需单独取证，不计为当前已复现新缺陷。

### P1-04 迁移目标校验缺口

- 入口：`scripts/migrate-env.sh` → `scripts/env-guard.sh` → 实际迁移连接。
- 历史证据 L：staging 配置中放入不同目标的虚构迁移 URL，守卫退出 0，未连接目标。
- 补验：应用/迁移目标不一致、直接连接与 pooler 合法差异、数据库名差异、缺少目标身份、误标 staging、合法 staging。
- 修复边界：验证实际项目/数据库身份，不能仅比较主机字符串或相信环境名称。所有迁移入口复用验证，错误须发生在连接或写入前的适当阶段。
- 关闭：虚构错目标被拒；已声明的合法地址别名通过；生产确认依据实际目标生效；保留脱敏判定记录，不输出密码。

### P1-05 测试 isolated 标记不足

- 入口：`vitest.shared.ts`、API setup/reset、seed 及可独立运行的种子脚本。
- 历史证据 L：虚构远程地址加 isolated 标记被配置接受，连接数 0，见 `test_guard`。未证明发生过生产写入。
- 补验：无 dotenv、环境变量覆盖、远程管理员 URL、同项目不同地址形式、合法本机独立库、普通开发库误传、直接调用 seed。
- 修复边界：统一验证真实测试目标，写入入口二次防御；本机地址仍需校验指定测试数据库身份，不能把所有 localhost 库都视作可清理。
- 关闭：错目标在首次危险操作之前失败；受保护数据库零写入；专用隔离库可完成 seed/reset；子进程及直接脚本不能绕过。

### P2-01 健康表令牌进入 URL/日志

- 历史证据 S：分享 URL 使用查询参数，前端读取该参数，Caddy 对该路径没有对应查询脱敏。
- 补验 B/S：首次页面请求、反向代理访问日志、浏览器历史、Referer、错误监控及分享预览；验证令牌过期、撤销、重复提交。
- 修复边界：fragment 接收及尽早清理地址，兼容旧链接时仍需日志过滤；前端后续改 header 不会撤销首次请求记录。fragment 方案本身也不是全部泄露面已关闭的证明。
- 关闭：新链接令牌不进入服务端 URL/访问日志；旧链接保护策略明确；合法提交、过期和撤销符合契约。历史健康答案读取不属于当前已证实影响。

### P2-02 持久离线契约失效

- 历史证据 S+D：订单响应 `no-store`，客户端据此不写 IndexedDB；报告时业务未调用离线读取函数。没有浏览器离线刷新证据。
- 补验 B：成功加载后断网，路由切换、页面重载、过期快照、退出/切店/换账号、重新联网及重复操作。
- 修复边界：先确定允许持久化的最小字段、TTL 和清理策略；保留敏感 HTTP no-store；页面实际接入离线读取及状态提示。
- 关闭：承诺的离线页面可恢复允许的数据并标示更新时间；无跨账号/门店残留；不承诺的操作明确禁用或按安全队列恢复。

### P2-03 CI 与发布验收脱节

- 历史证据 S+D：自动 CI 只检查规则和类型；旧全量初跑 6 失败。本次只读核对 verify.yml 仍未发现测试步骤。
- 补验：PR 故意引入确定失败用例；对应提交的检查结果、部署入口是否实际阻止发布；手动和紧急入口是否有可追踪规则。
- 修复边界：确定性快速测试自动运行；隔离完整验收绑定待发布 SHA；修正旧契约及随机测试，不能仅删断言制造绿灯。
- 关闭：失败提交不能通过规定发布门槛，合法提交可通过；每个旧失败有原因和验证记录。原初跑 2908 项中 2902 通过/6 失败保留，不被重跑改写。

### P2-04 依赖安全公告

- 历史证据：旧锁文件扫描 24 项（2 critical/12 high/10 moderate）；这是历史扫描统计，不是 24 个确认可利用的生产漏洞，也不是今日漏洞状态。
- 补验：依赖路径、运行时/开发时归属、实际启用接口、利用输入、当前维护者公告及修复版本、升级兼容性。
- 修复边界：按运行时与工具链分批升级；保留锁文件；不能将 Vitest UI server 公告直接称为生产 API RCE。
- 关闭：新锁文件扫描及升级后相关回归完成；剩余风险逐项写明暴露前提、处理责任和复查时间。本次未联网更新公告或重跑扫描。

## 5. 必须整条跑通的业务序列

1. **普通营业**：公开预约 → 占资源 → 到店 → 指派/开单 → 加项 → 合法优惠 → 混合收款 → 小费 → 小票 → 日结。逐步核对对象关联、金额、审计与权限。
2. **取消与退款**：预约/已收款 → 取消或部分退款 → 外部结果未知 → 重启恢复 → 再次重试 → 跨日归账。重复执行后净额及原始历史保持正确。
3. **权限变化**：技师正常查看本人 → 请求别人订单 → 会话等待时撤权 → 尝试改价/重放 → 换店。既验证拒绝，也验证合法业务没有被整体封死。
4. **电话与通信**：电话创建预约 → 用量上报重复/修订 → 权益抵扣 → 超额应收 → 失败重试。只对已实现的能力执行；capture、本地模拟与真实送达分别记录。
5. **断网操作**：加载门店 → 断网 → 页面重载/操作 → 恢复网络 → 服务端确认 → 退出换账号。检验可见状态、重复提交与缓存隔离。

每条序列输出最终业务事实，不仅输出 HTTP 200：预约占用数、有效工单数、收款/退款净额、任务/回执唯一性、审计记录、跨角色可见字段。
