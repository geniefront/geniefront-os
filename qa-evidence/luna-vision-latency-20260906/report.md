# Luna 识图延迟优化实测

2026-09-06。只测试，未改项目业务代码或模型配置。

## 为什么要30多秒

原始medium三次总耗时31.4–34.8秒，首次函数参数增量5.4–8.8秒，此后继续生成24.5–28.0秒。非推理输出约3542–3585 tokens。首输出前包括网络、排队、图像/输入处理与推理，不能全部当成识图耗时；首输出到结束也包括流式传输开销。主要已观测等待在长结构化输出阶段。

原始low有一次reasoning_tokens=0，总耗时仍34.99秒。max_output_tokens=32000只是上限，没有实际生成32000 tokens。

## 优化及结果

同一原图1080×1920、Luna、high图像精度、强制工具调用，每配置3次新会话。测试通道部分并发，保留缓存，没有自动重试。原始medium基线复用前一轮结果，不是随机交错的严格实验。

紧凑格式：分类只写一次；缩短字段名；只输出一份价格档位，由程序算最低价；非套餐pkg=null。保留名称、价格档位和标签、分类、kind、confidence、bbox、说明。增加unit保留each，强调未印核销次数填0。这是格式与提示约束的组合优化，不是纯字段重命名单变量实验，也不是已经接入业务的替换接口。

| 配置 | 完整耗时中位数 | 三次范围 | 相对49项基准逐次匹配 |
|---|---:|---:|---|
| 原始格式 / medium（前轮） | 33.3秒 | 31.4–34.8秒 | 49、49、49 |
| 紧凑格式 / medium | 22.8秒 | 20.2–25.2秒 | 49、49、49 |
| 原始格式 / none | 22.6秒 | 18.4–62.7秒 | 49、45、45 |
| 紧凑格式 / none | 12.7秒 | 12.5–14.2秒 | 49、49、45 |

紧凑medium完整时间中位数减少约31.5%，可见输出约2300 tokens，原格式约3500 tokens。三次均保留28个收费实体、49个价格时长条目、五个each单位；未印套餐次数均填0。

## 45/49的含义与限制

none的部分输出采用另一种治疗按摩价目归属：左两项只给60分钟119美元，右两项只给90分钟169美元，相对原基准缺少四档。

该区域两列布局存在解释空间。49条目基准采用四项目共用两档价目，但真实适用范围仍需店主确认。这些45/49应解读为“相对基准四档未保留，且未提示这处归属歧义”，不能视为已证明四个客观价格识别错误。

所有响应通过原有Zod校验。bbox保留但未评估位置精度，部分补拍追问质量未量化。只有一张独立图片，重复运行不等于覆盖更多店铺。原始none第三次62.7秒尾部耗时如实纳入，无法从已有数据确定原因。

## 建议（本轮未实施）

1. 优先紧凑格式+medium，当前样本完整草稿20–25秒。
2. 校验完一行或一组就展示草稿，完整校验前不提交最终保存。当前实现等待finalMessage和全量保存，前端每2.5秒轮询done；SDK流式并未把逐行结果展示给用户。
3. none可继续评估为清晰图片快速路径，复杂表头、单位缺失等触发medium复核；不能只依赖模型自报置信度。
4. 不通过压低图像清晰度或硬截断输出换速度。多张图再评估受控并发；单图分块要保留共同表头和价格说明。
