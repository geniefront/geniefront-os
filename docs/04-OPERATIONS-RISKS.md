## 1. 获客与开店：做极简升级，不做沉重迁移 ⭐⭐⭐

**已定战略：不考虑替代 Vagaro / Mindbody 这类存量成熟 SaaS 客户**。
我们的核心客群是目前依赖**纸质小本子、手写单、Excel、微信群接龙、老旧单机土系统**记账的亚裔门店。

这意味着：
- **卸掉包袱**：不需要做复杂的竞品巨型数据解析与格式逆向工程。
- **5 分钟拍照开店**：开店只需要老板拍照上传价目表 + 填入几个技师名字和营业时间，AI 自动提取生成项目与价格，前台直接投入使用。
- **基础导入**：如果老板有简单的 Excel 客户表（仅包含姓名、手机号），提供最轻量的 2 列 CSV 映射导入。
- **现场共创陪跑**：前 3 家种子店亲自到店（或远程视频）守一天，看纸质轮牌如何平滑过渡到屏幕轮牌。

## 2. 你的用户不会用软件 ⭐⭐⭐

技师群体：40–60 岁为主、英文不好、戴着手套、手上有甲油、店里很吵、一边做客人一边操作。

产品含义：
- 按钮 ≥ 56px，字号 ≥ 16px，高对比。**图标优先于文字**
- 一个任务一屏完成，不要多层弹窗
- 员工端**全屏一次只显示一件事**（下一位客人 / 打卡 / 我的收入 三个大块）
- 界面语言按人设置，第一次登录就问"你说什么语言"
- 关键操作要有**语音输入**（说中文/越南语 → 转文字 → 填备注）
- **不要用颜色作为唯一信息载体**（有色觉障碍的人 + 廉价 iPad 屏幕）
- 培训：每个功能配 60 秒竖屏视频，多语言配音（AI 配音即可）

前台是另一类人：快、熟练、要键盘。**Desk 端高频操作必须键盘可完成**（搜客人、开单、结账、叫号）——他们每天点几百次，纯触屏会让前台觉得慢，而 Desk-Only 模式下前台还要代技师做所有事，操作量再翻倍。做法是**双轨**：≥56px 大按钮与快捷键并存，快捷键可在设置里整体关闭（怕误触的店直接关）。**危险操作（作废 / 退款 / 删除）永不绑快捷键**，只能点按钮 + 二次确认。Staff / Kiosk 端不设任何快捷键。

## 3. 硬件问题，纯 Web 会撞墙 ⭐⭐

美国门店结账要给**小票**。浏览器打不了热敏小票机 —— 这是纯 Web 方案最容易漏掉的坑。

三条路，建议 Phase 3 之前决定：
| 方案 | 说明 | 评价 |
|---|---|---|
| 云打印机（Star CloudPRNT / Epson ePOS） | 打印机自己轮询你的服务器拉任务 | **推荐**。纯云、无需本地软件、和 Web 完美配合 |
| 本地打印代理 | 门店装一个小程序，Web 通过 localhost 调用 | 要装东西，支持成本高 |
| WebUSB / 系统打印对话框 | 浏览器限制多，排版差 | 只作兜底 |

其他硬件：
- **钱箱**：一般由小票机的 RJ11 口驱动 → 选云打印机时确认支持 kick-drawer
- **前台设备**：建议标准化推荐一套（iPad 12.9 或便宜 Windows 一体机 + 云打印机），减少支持成本
- **网络**：很多店只有一条便宜宽带。建议要求装 4G/5G 备份路由（$30/月），比你写离线代码便宜一百倍
- **Kiosk iPad**：需要引导模式（Guided Access）防客人乱点

## 4. 单位经济：AI 和短信是真金白银 ⭐⭐

量级参考（以实际账单为准）：

| 项目 | 大致成本 | 计在谁头上 |
|---|---|---|
| Supabase Pro | $25 / 月起 | 平台（全部门店共用） |
| 应用实例 × 2 + Cloudflare LB | ~$40–60 / 月 | 平台 |
| Telnyx 号码 | **~$1 / 月** + inbound ~$0.002/分钟 | 每店 |
| 10DLC | brand 一次性 + campaign 月费 | **平台**（前 ~200 家共用一个 brand，见 `09` §5）⚠️ 之后转每店 |
| 短信 | ~$0.01 / 条（含运营商附加费） | 每店 |
| **Telnyx AI Assistant** | **$0.062 / 分钟**（全套：平台 + 电话 + ASR/TTS + LLM） | 每店 |
| **前台副驾 LLM** | **~$0.012 / 次**（缓存命中后，见 `05` §7.1） | 每店 |

### 4.1 定价：套餐含额度 + 两种独立额度充值 ⭐⭐

**2026-08-17 定稿**，数字来自实测成本，不是估算。

| | 月费 | 含 AI 积分 | 含 AI 语音 | 我们成本 | 毛利 |
|---|---|---|---|---|---|
| **Essential** | **$99** | 500 | **60 分钟** | $8.72 | **91%** |
| **Growth** | **$199** | 1200 | **500 分钟** | $43.00 | **78%** |
| **充值** | **$50** | 1000 积分 | 或 200 分钟 | — | 80% / **75%** |

**加权后的生意毛利 81%**（收入 $169 / 成本 $32.72，按 3:7 分布），70% 的店会落在 Growth。

#### 1 积分 = $0.01 的真实成本，向上取整

不是拍脑袋定的。实测（`05` §6.0，`claude-sonnet-5`，缓存命中后）：

| | 成本 | 扣几个积分 |
|---|---|---|
| 只读回答 | $0.003 | 1 |
| 带一轮工具的提案 | $0.010 | 2 |
| 复杂提案（多工具） | $0.034 | 4 |
| 拍照开店一张（Opus） | $0.080 | 8 |

所以「平均一次操作扣 1 积分」自然成立，而拍照开店按同一把尺子自动扣得多 ——
**不需要为它单独定一套规则，也不会有人拿它当免费午餐**。

⭐ **关键词直接答掉的不扣积分**（`05` §7.2 第 3 条的确定性路由）。
那些根本没走模型，我们零成本。而「常用查询不算积分」是个实实在在的卖点，
比偷偷扣掉诚实。

#### ⚠️ 两种额度不能互换

语音成本 **$0.062/分钟**（2026-08-18 实测，**全套算**：平台 + 电话 + ASR/TTS + LLM），
是一次副驾操作的 **6.2 倍**。
只要两者能换，客户就会把额度全换成最贵的那种用 —— 而那恰恰是最忙、
最该赚钱的客户。代码里**没有任何换算函数**（`@gf/payroll/credits` 有一条
测试专门守着这件事）。

#### 为什么 Essential 只给 60 分钟

**这是有意的，而且是算过三种配法之后才定的。**

语音是成本大头。Essential 给 200 分钟的话：它自己的毛利从 91% 掉到 82%，
而且**没人会升级到 Growth** —— 实测同样用量下 Essential 反而更便宜：

| 门店用量（月） | Essential | Growth | 谁便宜 |
|---|---|---|---|
| 清淡 3 通/天 | **$140** | $199 | Essential |
| 一般 10 通/天 | $271 | **$261** | Growth |
| 中度 15 通/天 | $372 | **$355** | Growth |
| 忙店 25 通/天 | $580 | **$543** | Growth |

60 分钟 ≈ 每天 1 通电话 = **「尝鲜」不是「够用」**。
升级 +$100 买到 $145 的量，推力明显。

⚠️ **销售时必须直说**：开店时问一句「一天大概接几通电话」，
超过 2 通就直接推 Growth，别让老板自己撞上账单。

#### 还没定的

- ✅ **单价已确认**（2026-08-18）：**$0.062/分钟，全套**（平台 + 电话 + ASR/TTS + LLM
  都算进去了，不用再担心「是不是全包」）。比原估的 $0.056 高 11%，上表已按此重算。
  验算：Essential `60×$0.062 + 500×$0.01 = $8.72`、Growth `500×$0.062 + 1200×$0.01 = $43.00`。
  ⚠️ **充值买分钟那一档毛利掉到 75%**（$50 / 200 分钟，成本 $12.40）——
  这是所有档位里最薄的一条，分钟单价再涨就要动这个价。
- ⏳ **关键词路由能拦掉多少提问**（现按 65% 估）。代码在日志里记了
  `source: local | model`，**上线后捞一周真实数据再定稿**。
  如果实际只有 30%，Essential 的 500 积分会紧很多。

### 4.2 10DLC 在规模化时的固定成本（最容易漏掉的一笔）⚠️

每家店一个 campaign × $10–15/月 = **1000 店时每月 $10,000–15,000 的纯固定成本**，占 $99 × 1000 的 **10–15%**。

短信已推迟到门店 ≥ 10 家之后（`03` 决策 11），但**在启动 Phase 2.5 之前必须先找 Telnyx 销售确认批量 campaign 报价与托管架构** —— 这笔钱可能反过来推翻定价档位，属于"晚知道会很痛"的那一类。

⚠️ 换 CSP 还有一笔隐性成本：**10DLC 要在新供应商名下重新排队**（`09` §1.1）。

**必须做：**

- `usage_events` 从第一天记录，**`ai_assist` / `ai_call_min` / `sms` / `email` 四种分开计量**
- **硬性上限与告警**（防止一家店的 AI 死循环烧掉你一个月利润）
- 前台副驾用**便宜快模型做意图识别 + 贵模型只在复杂场景**，并对现场快照做缓存
- 试用期必须限额，否则会被薅

## 5. AI 电话的风险，必须设护栏 ⭐⭐

**下面每一条护栏与供应商无关**。从"能用"到"1000 家店无人值守"之间的坑：

- **误订/幻觉**：AI 报了一个其实没有的空档，或听错电话号码。
  → 所有 AI 创建的预约标 `source=phone_ai`，**进前台的"待复核"队列**，前台一眼扫过。
  → AI 只能从**排期引擎返回的真实空档**里选，不许自己算时间。
- **通话录音同意**：加州、宾州等是 **two-party consent 州**，录音必须开场告知。做成模板化开场白 + 按州自动启用 ⭐
- **转人工**：处理不了必须能转前台电话或留言，不能挂断
- **营业时间外**：明确策略（AI 接 / 留言 / 转语音信箱）
- **口音与多语言**：你的客人说带口音的英语、粤语、越南语。**必须实测**（换供应商后要**重新测一遍**，标准见 `09` §4.3），并给每家店配"AI 语言集"
- **成本失控**：单通话时长上限
- **责任边界**：AI 报错价格怎么办？ToS 里写清，产品里让 AI 只读价目表不许自由发挥

## 6. 会有店主要求你做违法的功能 ⭐⭐

现金业务的必然：会有老板要求"这单不入账"、"删掉这条记录"、"改上个月的营收"。

**产品立场（建议写死）：**
- 财务记录 **append-only**，只能 `void`（作废）且必须留原因、留操作人、进老板报表
- 不提供"删除历史交易"、"批量调整营收"这类功能
- 不提供"雇主抽取小费"选项（联邦法禁止，见 `00-DISCOVERY.md` §3.2）
- 薪酬/小费设置页统一提示"请与您的会计/劳动法顾问确认"

这既是保护客户，也是保护你 —— 你不想在别人的税务或劳资案子里被传唤。同时这反而是卖点：**"老板可以放心把店交给店长"**（防内盗）是华人店主最痛的点之一。

## 7. 数据模型上的现实陷阱

- **共用手机号**：夫妻/母女共用一个号码很常见。`(org_id, phone)` 唯一会挡住第二个人。
  → 允许同号多客户，但录入时提示"该号码已有 2 位客人：张女士 / 张先生"，让前台选 ⭐
- **家庭/团体预约**：一家四口一起做美甲 = 一个 party、4 个客人、4 个技师、要一起结账
  → `appointment_links` + 结账时可合并成一张 ticket
- **同名客人**：美国华人店里 5 个 "Amy Chen" 很正常 → 列表必须显示手机后四位
- **技师换手机号频繁** → 登录恢复流程要有店长代为重置
- **姓名**：西语姓名有两个姓、越南语姓在前、中文名有拼音和汉字两版 → 存 `display_name` 不要强拆 first/last 用于展示
- **客人不给电话**（walk-in 只做一次）→ 允许匿名客人，事后可合并
- **订单取消的复杂副作用**：前台会因各种原因（包括外部辅助记账后的取消）取消订单。
  → **取消原因菜单**：必须提供标准化的下拉菜单（如“Duplicate Booking 重复预约”、“Walk-Out 客人走单”、“Guest Changed Mind 客人改变主意”、“Input Error 录入错误”），以规范化取消记录，避免审计日志异常。
  → **轮牌隔离防错补丁**：如果订单取消时技师已经被占用，系统**必须弹窗询问“是否为该技师保留本次轮牌(Turn)与日程占用时长？”**。否则系统会默认技师未工作，释放档期并打乱轮牌队列，导致门店排班大乱 ⭐⭐⭐

## 8. 支持成本会淹死你 ⭐

1000 家店 = 每天几十个"我点不进去了"。前置设计：

- **模拟登录（impersonate）**：能一键以某店身份看到他们看到的界面（双人确认 + 全程审计 + 顶部红色横幅）
- 每个页面右下角"报告问题" → 自动带上店 ID、当前页面、最近 20 条操作、浏览器信息
- **状态页**（status.xxx.com）+ 系统内公告推送
- 帮助中心多语言 + 60 秒视频
- **上线节奏**：先 3 家 → 稳定后 30 家 → 再放开。别一次上 100 家，你会被支持工单埋掉 ⭐

## 9. 评价与口碑的合规

- **不能只邀请好评**（review gating）—— Google 明确禁止，被发现会掉评价甚至处罚。产品要**对所有客人一视同仁地邀请**，可以做的是：先发内部满意度 → 都发 Google 邀请，只是对不满意的额外触发内部跟进工单。
- 不要代客人写评价、不要用 AI 生成假评价（Google/Yelp 会检测，FTC 2024 起对虚假评价有明确罚则）

---

## 10. 备份不是开个开关

- PITR 开了不等于能恢复。**每季度真做一次恢复演练**，记录 RTO
- 每日逻辑备份（`pg_dump`）到 R2，异地保存，加密
- **门店自助数据导出**（客户+预约+交易 CSV）—— 既是信任卖点，也是 CCPA 要求
- Supabase 单区意味着区域性故障你只能等。写进 SLA，别承诺 99.99%

---

## 11. 安全清单

- `impersonate` 必须双人确认 + 审计 + 通知门店
- 离职 membership 立刻断权（会话也要吊销，不能等 JWT 过期）
- PIN 只有 4 位 → 必须限制：只能在门店设备上用、错误 5 次锁定、不能用于远程登录
- 健康表数据应用层加密，读也审计
- 公开预约 API 加 Turnstile + 速率限制（防刷号、防恶意占位）
- 依赖漏洞扫描 + secrets 扫描进 CI

## 12. 竞争与定位

主要竞品：Vagaro（便宜、界面老）、Boulevard（高端沙龙、贵）、Mindbody（大而笨）、Zenoti（连锁企业级）、GlossGenius（个人从业者）、Booksy。

**他们都做不好的、正好是你的护城河：**
1. **多语言**（尤其越南语/韩语/中文的员工端）—— 美国 nail 行业越南裔占多数，没有一家竞品认真做越南语
2. **轮牌 / 点钟制** —— 这是华人/越南裔店的运营核心，美国主流软件根本没有这个概念
3. **小费与提成的复杂分配** —— 竞品都很僵硬
4. **AI 前台 + AI 电话** —— 现在还是空窗期，但窗口不会开太久

定位一句话建议：**"给华人/亚裔服务业开的、会说你员工语言的 AI 前台系统。"**

**定价竞争力：**

| 竞品 | 月费 | 我们的优势 |
|---|---|---|
| Vagaro（1 技师） | $25 | 不支持轮牌、现金分配僵硬、无 AI |
| Vagaro（5 技师） | $85 | 同上，且按人数定价让老板反感 |
| Mindbody Starter | $139 | 笨重、不懂亚裔运营 |
| 法拉盛土系统 | $500–$2000 买断 | 无云、无移动端、无 AI、界面丑 |
| **我们（Essential）** | **$99** | **全功能不限技师 + 500 AI 积分 + 60 AI 电话分钟** |
| **我们（Growth）** | **$199** | 以上 + 1200 积分 + **500 分钟** |

核心卖点：$99 全功能不限人数，比 Vagaro 5 人版还便宜，且包含轮牌 + 小费分配 + AI 副驾 + 多语言。不做按技师人数定价（技师流动大，老板不想因为临时多一个人就升级套餐）。

⭐ **套餐口径以本文 §4.1 为唯一事实源**（`essential` / `growth`，迁移 0021）。
早期文档里的 `Starter` / `Pro` / 「AI 电话包 $69」**已作废**。AI 电话不再单独成包 ——
它是套餐里的分钟额度，用完了充值（积分与分钟**两本独立的账**，不能互换）。

## 13. 获客策略：口碑裂变是唯一出路

本产品的核心卖点（外部结算辅助、现金分配灵活性等）**不能在公开营销材料里直接说**。传统 SaaS 获客（Google Ads、SEO、Product Hunt）效果有限。

**有效渠道：**
1. **华人美业微信群 + 小红书**：让种子用户在群里现身说法，暗示性口碑传播最有效
