# 全面审查计划

> 范围：v1 `geniefront-os`。不涉及 v2。
> 起始：2026-09-11。本文件是总纲与进度台账，各线的详细发现写进各自的报告。

## 为什么是这九条

前三轮（iPad 外壳、反馈状态、校验与骨架屏）审的是**用户当场看得见的东西**。
剩下的风险恰好相反：出问题时用户看不见，或者看见时已经晚了 —— 少收了一笔钱、
越权读了一次健康表、断网重试写进两条记录。九条线按「漏了会怎样」排序，
而不是按工作量。

## 排序依据

| 线 | 漏了的后果 | 可自动化 |
|---|---|---|
| A 权限对账 | **越权**（安全） | 高 |
| B 钱路径口径 | **账对不平**（财务） | 中 |
| C 弱网与幂等 | **重复写入**（数据） | 中 |
| D i18n 渗漏 | 用户看到原始 key（体验） | 高 |
| E 打印出纸 | 小票印不出（营业中断） | 低 |
| F 安全面 | XSS / 越权读（安全） | 中 |
| G 测试厚度 | 回归无护栏（长期） | 高 |
| H 长列表性能 | iPad 卡顿（体验） | 中 |
| I 键盘与对比度 | 可达性（合规） | 中 |

## A. 权限矩阵对账 ⭐ 最高优先

**要回答的问题**：前端画出来的每个写入口，与服务端对同一命令的判定，是否同一条权限？

后端是单点判定（`apps/api/src/bus.ts:121`，按 `COMMAND_REGISTRY` 中每条命令声明的
`permission`），这一点大幅降低了后端漏判的概率。因此对账的重点落在**前端**：

- A1 命令 → 权限：从 `COMMAND_REGISTRY` 机器提取，作为唯一事实来源
- A2 前端调用点 → 命令：扫描前端实际发出的每条命令
- A3 前端调用点 → 门禁：该入口被 `useCan*` / `GuardedButton` 的哪条权限守着
- A4 差异表：A2 ∩ A3 与 A1 不一致的格子
  - **漏门禁**（前端没守 → 点了 403，用户读作系统故障）
  - **错门禁**（守的权限与服务端要求的不是同一条）
  - **过严门禁**（前端比服务端更严 → 有权限的人看不到入口）
- A5 无 `permission` 声明的命令逐条复核：是真的公开，还是漏写
- A6 五个角色预设逐页走查（此前只走过 `front_desk`）

**产出**：`2026-09-11-permission-matrix.md` + 一个可重复运行的对账脚本

## B. 钱路径数值口径

前一轮只修了**输入校验**。真正的钱在计算侧。

- B1 前后端取整方向对账（前端校验层已明确选「截断」，服务端是否一致）
- B2 分账、税费、小费、折扣叠加的计算顺序
- B3 退款与作废的金额路径
- B4 找出其余「宽容解析器被当验证器用」的同类（`dollarsToCents` 是第一个）
- B5 金额相关的边界：0 元、负数、超大额

**产出**：`2026-09-11-money-path.md`

## C. 弱网、中断与幂等

已有基础：`lib/offline.ts` 不只信 `navigator.onLine`（还有心跳探测），
`GuardedButton` 有离线拦截，命令契约层有 `idempotency: 'required' | 'optional'`。

未验的是**中断路径**：

- C1 `idempotency: 'required'` 的命令，前端是否真的每次都带了幂等键
- C2 幂等键的生成时机（在重试之间必须稳定，否则形同虚设）
- C3 `retry: 1` 与写命令的组合：重发会不会产生两条
- C4 乐观更新在断网时的回滚
- C5 恢复联网后的状态一致性

**产出**：`2026-09-11-offline-idempotency.md`

## E. 打印出纸 ✅

既有的 `scripts/check-print-layout.mjs` 比预期完整：chromium **与 webkit**
（Safari 引擎）双跑、Letter 与 80mm 各出一份 PDF、横向溢出断言、120 行长表分页、
取消/重打/关闭的完整交互。E1 与 E3 复核通过。

**缺口只有一个：58mm 这一档根本不存在** —— 纸张选项里只有 Letter 和 80mm。
而美甲店用的小票机多半就是 58mm，它比 80mm 窄近三成，长项目名与
「小计 / 税 / 小费」那几行最先在这里溢出。

已补：
- `PrintPaper` 增加 `thermal58`，可打印宽度按与 80mm 相同的留边推算（80→74，58→52），
  字号再收一档（否则长项目名换行过密，一张小票会拉到两倍长）
- 小票与**服务单**两处选择器都加上这一档
- `check-print-layout.mjs` 增加 58mm 的溢出断言与 PDF 产出

实跑验证：chromium / webkit 双双 PASS，并人工看过 58mm 的出纸截图 ——
长项目名换行干净、金额列完整、没有被切。
