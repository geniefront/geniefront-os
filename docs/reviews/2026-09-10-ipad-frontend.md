# GenieFront OS 前端 iPad 审查

范围：现有 `apps/web` 统一前台与 `apps/ipad` 自助终端。检查共享排版、导航、输入、弹窗、主要页面的响应式类和签名交互。没有修改 v2、后端、数据库或业务契约，没有部署。

## 已修复

| 问题 | 修复 |
|---|---|
| 平板辅助文字多为 8–12px，常规文字 14px | Web 在 600–1400px 使用 14px 辅助文字、16px 常规文字；覆盖历史任意小字号。保持 rem 间距不变，避免整体放大导致布局溢出 |
| 小按钮和小输入框难以触控 | 触屏 Web 按钮至少 44×44px，文本输入至少 44px 高、16px 字号；Kiosk 至少 48px，原有 56px 主操作保留 |
| 1024px 横屏提前展开桌面侧栏，挤压业务内容 | 常驻侧栏移到 1280px；较窄平板使用可展开导航 |
| 桌面折叠后旋转至竖屏，菜单标签继续隐藏 | 桌面折叠偏好与当前视口分别处理，监听断点变化 |
| 隐藏导航仍可通过键盘聚焦、触摸关闭菜单不够直接 | 关闭导航设为 inert，增加展开状态语义，支持 Escape；外部点击监听改为 pointerdown |
| 收银在 768px 就横排固定宽列表 | 1024px 以下纵排，列表限制高度；窄屏容许页面纵向滚动 |
| 消息页面三栏过早展开、纵排仍保留固定整页高度 | 平板两栏，客户资料放下一行；1280px 以上三栏；仅大屏使用固定工作区高度 |
| 通知页竖屏四张统计卡片与筛选栏拥挤 | 平板统计两列、筛选与搜索分行 |
| 全屏安全区与浏览器动态高度 | Web 壳层添加安全区，Kiosk 使用 dvh 和可收缩滚动主体 |
| Kiosk 禁止缩放 | 移除 viewport 的缩放限制及 body 的单轴 touch-action 限制，签名区域继续独立禁止滚动 |
| Kiosk 安装提示盖住提交操作 | 改为占据正常布局空间；安装说明弹窗支持小高度滚动 |
| 签名画布初始化后宽度写死 | 显示宽度跟随容器，落笔坐标转换到原始画布，旋转不重置已有笔迹；处理触摸取消 |
| 最后一笔撤销后保存空白图片 | 调用 onClear，避免空白图片仍充当有效签名 |

## 验证

- Web：59 个测试文件、365 项测试通过。
- Kiosk：10 个测试文件、21 项测试通过，包含新增签名坐标与撤销回归。
- 两个应用 TypeScript 检查与生产构建通过。
- Chromium 触屏模拟：600×900、768×1024、820×1180、1024×768、1180×820、1366×1024。
- 登录和配对页的文档宽度无溢出，输入框实测 16px。
- 主导航在上述尺寸验证关闭/打开、44px 触控高度、Escape、桌面折叠后转竖屏的文字恢复。
- 浏览器截图位于 `artifacts/ipad-review/`。复现：分别启动 Web Vite 5187、Kiosk Vite 5188，再运行 `node scripts/check-tablet-layout.mjs`。

## 验证边界

主导航检查使用仅在浏览器内注入的模拟会话，并阻断业务 API；没有执行真实预约、收银或消息发送。收银、消息、通知的布局修改完成代码审查与构建验证，但未对每一种真实数据/权限/语言组合做完整业务回归。当前机器未安装 Playwright WebKit，尚未进行真实 iPad Safari、软键盘弹出和 Apple Pencil 验证。构建仍提示 Kiosk 主包偏大，未在这次屏幕适配中拆包。
