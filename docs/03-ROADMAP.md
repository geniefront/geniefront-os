| 21 | **客户唯一凭证是 `customers.id`** ⭐ | 手机号**不是**唯一键（夫妻/母女共号很普遍），只是查找键。同号多客户必须走前台选择器，默认不自动匹配。弱唯一只挡"同号同名"的重复录入（`02` §5） |
| 22 | **AI 供应商** ⭐ | **Anthropic**（`claude-opus-5` / `claude-sonnet-5` / `claude-haiku-4-5`）。评估过 DeepSeek：函数调用可用、便宜一个数量级，但**不支持图片输入**，做不了价目表拍照提取（`04` §1 的头号卖点）；且"五点挪到六点"被解析成 06:00。已实测 Sonnet 5 视觉 + strict tool use 提取价目表，开放价与加项均识别正确，单图约 $0.011 |
| 23 | **副驾快照不脱敏** ⭐ | 前台副驾的现场快照带客人真实姓名与手机号，**不做脱敏** —— 前台需要一眼认人，脱敏会拖慢高频操作。技师端的手机号脱敏（决策 16）不受影响，那是防挖客，两回事 |
| 24 | **审计留动作不留金额** ⭐ | `audit_log` 对 ticket / payment 只记 `command / actor / entity_id / at`，**金额字段不写入 before/after**。折扣、作废、退款的动作本身照常留痕。工单流程必须完整走完（现金还是刷卡要到结账那刻才知道），结账后可**正常入账**或**作废**（必选原因，记录保留但不计营业额）。**不做取消率异常监控** |
| 25 | **资源可以有容量** ⭐（2026-08-16 补） | 一间房**能同时服务多人多技师**：足疗房排 6 张躺椅、双人房两张床两个技师、美甲区整片当一个资源用 ——「一房一客」在真店里反而是少数。`resources.capacity`（默认 1）+ `max_staff`。资源**仍是数据库硬约束**（宪法第 15 条不变），只是实现从 GiST 排他约束换成**计数触发器**：排他约束表达不了「最多 N 个」。触发器里先锁 `resources` 那一行，把排他约束原本免费给的并发保证拿回来 |
| 26 | **一组客人：合并付款与分别付款都要顺** ⭐（2026-08-16 补） | 一起来的几位**每人各一张单**，用 `ticket_groups` 串起来 —— 提成/小费/轮牌全部按人次算，合成一张就再也拆不回去。归组动作对**已经开着的单**也能用，因为「我请客」是在结账台说的。合并结账时，折扣与小费按各单金额最大余额法摊，实收的现金/刷卡额用**整数桶填充**摊回各单：按比例摊只能保住「每张单的账」或「每种支付方式的合计」之一，而后者对不上就意味着晚上点钞对不上 |
| 27 | **现金实收、找零与「不用找了」必须落账** ⭐（2026-08-16 补） | 客人给 $100 做 $85 的活儿说「不用找了」，那 $15 **必须记成小费**。不记的话打烊点钞平白多出 $15，而老板唯一能怀疑的对象是前台。`payments` 加 `tendered_cents` / `change_cents` / `keep_change`，DB 约束兜底。结账页把它做成**一次点击**的动作 —— 客人正站在柜台前等着，前台没工夫心算小费该改成多少 |
| 28 | **AI 语音与短信统一走 Telnyx** ⭐（2026-08-18 定稿） | 号码 + 语音信道 + AI Assistant 编排 + 短信，Telnyx 一家全出：一个供应商、一份账单、一套 webhook 签名。**已实测打通**（`09` §4.3，关键是 Speaking Plan wait 要调高）。全包 **$0.062/分钟**（实测，含平台+电话+ASR/TTS+LLM）。接入靠**呼叫转移**不做 porting（`09` §2）。⚠️ **换 CSP 意味着 10DLC 重新排队**，Telnyx 批准前不要注销 Twilio 那边的申请。LLM 供应商仍是 Anthropic（决策 22 不变），电话只是它的一条入口 |

## B. 分期（每一期结束都必须"能进真店从早用到晚"）

> **排期是乐观值。** 按功能密度，Phase 0 → 2 大约 22 周 ≈ 5.5 个月（1–2 人）。
> 唯一不能妥协的是 **Phase 1a 必须最先落地并进真店** —— 它决定这个产品成不成立。

### Phase 0 — 地基（1–2 周）

- Monorepo（`geniefront-os`）、`packages/contracts`（Zod）、**命令总线**、审计日志、错误码
- Supabase 项目（dev / prod）+ Drizzle migrations + **强制 RLS 模板** + `audit_log` append-only trigger
- 种子数据：2 家假店（一家 nail、一家 foot spa）
- 认证：Supabase Auth 邮箱 Magic Link + **多店选择器** + 设备令牌 + PIN
- i18n 骨架（en / zh-Hans / zh-Hant / ko / vi / es）+ 设计 token（大字号、高对比、图标优先）
- 计费骨架：`location_subscriptions` + `usage_events`（**`ai_assist` 与 `ai_call_min` 分开计量**，先只记录不接 Stripe）
- 部署：Fastify Docker 镜像 → 开发 1 台实例
- CI：typecheck、单测、迁移检查、镜像构建，加两条硬 lint：
  - 源码出现裸 `SET ` 而非 `SET LOCAL ` → 失败
  - `apps/**` 里出现 `SUPABASE_SERVICE_ROLE_KEY` → 失败（只允许 `packages/db/**`）

**验收**：跑通 `appointment.create`，产生审计记录，RLS 阻止跨 org 读取，多店切换正常。

### ✅ Phase 1a — Desk-Only 核心闭环（**已完成 2026-08-15**）⭐ 决定生死

> **交付状态**：全部条目已实现并部署到生产（api.geniefront.com，双实例 + LB）。
> 106 项测试覆盖三个纯函数引擎与 RLS/宪法约束。
> **验收标准「一家真店只用前台一台电脑跑完一整天」的路径已打通** ——
> 下一步是让种子店真用一天（见 `04` §14 与《种子店前台试用指南》），
> 而不是继续加功能。

> **范围原则**：这一期唯一的目标是**让一家真店扔掉纸质本子**。
> **Staff PWA、实时推送、提成引擎、日结点钞全部不在这一期**，它们在 1b / 1c。
> 理由：种子店按画像（40–60 岁老技师、不用手机）跑的就是 Desk-Only 模式（`00` §8 模式 A），
> Staff PWA 在这一期是纯负债 —— 这也正是宪法第 14 条的直接推论。

- ✅ 极简开店配置：项目/价格/技师/营业时间/**容量设置**（常用时长一键选、七天一键铺开）
- ⏳ 落单要素 `service_option_defs`：按 `business_type` 出预设种子（按摩力度/部位、美甲甲型/色号/卸甲、头疗头皮类型、美睫卷翘/胶水敏感），大按钮图标网格 + **sticky 回填「跟上次一样」**（`02` §3.1）
- ✅ **一人多角色**：`is_bookable` / `in_rotation` 两个开关（店长兼技师、老板临时下场）
- ✅ 日程表：**按技师列**，重叠单并排渲染，日视图；**点选改期**（拖拽推到 1b）
- ✅ **容量与超卖**：资源硬约束 + 技师/门店软告警 + 强行安排记原因（`01` §7.1）
- ✅ **轮牌板**（事件溯源）：整轮/半轮、跳过、指定不计轮、**手动拖拽调序 + 强行改派 + 原因流水**
- ✅ 客户：手机号查找 → **同号多客户选择器** → 建单；匿名 walk-in；客户合并
- ✅ 派单 → 开单 → **前台代加钟/加项** → 结账（现金/刷卡记录）→ **正常入账 或 作废（必选原因）**
- ✅ **小费分配引擎 v1**（含 FLSA 法律护栏）+ **一键复制微信 emoji 格式分配明细**
- ✅ **断网只读看板**（`01` §12）：橙色横幅 + 轮牌/日程只读快照 + 写操作置灰

**验收**：一家真店**只用前台一台电脑**，靠 Walk-in + 手动排预约 + 轮牌 + 结账跑完一整天，彻底抛弃纸质本。

- 生产镜像 78MB（esbuild 单文件打包）

**推迟到 1b 的**：

### 🚧 Phase 1b — 钱与班表（**核心四项已完成 2026-08-16**）

> **交付状态**：老板要的四件事已经跑通并有测试覆盖 ——
> 提成引擎与收入看板、打烊日结对账、现金小费发放、排班周模板与报表 CSV。
> 测试从 106 项涨到 **185 项**。
> **剩余项（见下方 ⏳）不阻塞种子店试用**，可以边用边补。

已完成：

- ✅ **提成引擎 v1**（`packages/payroll/commission.ts`）+ `compensation_plans` / `earnings`
  - 四种方案：纯提成 / 纯时薪 / 保底（两者取大）/ 租椅（引擎已支持，UI 在 Phase 2）
  - 分类费率覆盖、零售独立费率、双技师按「分钟 × 角色权重」分摊
  - **小费永不进提成基数**（引擎的输入类型里没有这个字段）
  - **提成基数折后还是原价必须显式选** —— 折扣算谁的是真店头号争议
- ✅ **技师当日收入看板**：每个数字可展开看依据，现金小费单列（今晚就要拿的钱）
- ✅ **打烊日结对账**：按面额点钞、现金进出、刷卡机 batch total 比对、差异必填原因、封账/重开
- ✅ **每日现金小费发放**：按人汇总（含昨日结转）→ 给出要数的面额清单 → 确认入账 →
  自动记现金出账 → 零头结转明天
- ✅ **排班周模板**：一键铺开一/两周（**绝不覆盖手工调过的班**）、单日改班/请假、发布给技师
- ✅ **基础报表 v1**：Gross / Discount / Net / Tax / Tips / Total + 现金刷卡拆分
  + 按天/按技师/按项目 + **CSV 导出**（服务端生成，带 BOM 与公式注入转义）

同期补的三件真店里天天发生、Phase 1a 表达不了的事（决策 25–27，见 §A）：

- ✅ **房间多容量**：一间房同时服务多人多技师。资源仍是数据库硬约束，
  只是从 GiST 排他约束换成计数触发器（排他约束表达不了「最多 N 个」）
- ✅ **组单**：一起来的一组客人，可以一人付全部，也可以各付各的
- ✅ **现金实收 / 找零 /「不用找了」**：找零转小费必须落账，否则打烊点钞对不上

顺手修掉的 Phase 1a 缺陷：

- 🐛 `ticket.void` 原本 `delete from tip_allocations`，而 0005 已对 `app_user`

  之所以一直没被撞见：作废通常发生在结账前，那时还没有分配行。

## D. 项目宪法（写进 `CLAUDE.md`，防止再次跑偏）

1. **所有写操作必须是命令**（有名字、Zod schema、权限、幂等键、审计）。页面里不许直接 `POST` 裸接口。
2. **排期、轮牌、小费三件事只能有一份实现**，在 `packages/*` 里，纯函数，必须有测试。
3. **前台拥有最终人工裁决权**：允许手动拖拽轮牌与强制插单，但必须记录操作人与原因流水。
4. **金额只用整数分**；`tip` 与 `service_charge` 永不混用；百分比一律 basis point。
5. **每张业务表带 `org_id` + `location_id` 且开 RLS**。应用用受限角色 `app_user` + 事务内 `SET LOCAL`，
   永远不用裸 `SET`。**`service_role` 只有 `packages/db` 的迁移与种子脚本可以读**——
   `apps/*` 里出现这个变量名，CI 直接失败。开发期把 dev 项目的 key 放 `.env` 无妨，
   **生产那一把只进 CI Secret**。
   > 理由不是洁癖：业务查询一旦走了 service_role，RLS 被静默绕过，
   > 所有租户隔离测试会**全部通过但毫无意义**，直到线上串了数据才发现。
6. **AI 的权限 ⊆ 操作人的权限**；写操作默认需要确认；一切可撤销；AI 产生的数据要有 `source` 标记。
7. **没有硬编码文案**，全部走 i18n key；店主内容用多语言 jsonb。
8. **时间存 timestamptz，展示按门店时区**；营业日边界（`business_day_cutoff`）有明确定义；DST 那两天必须有测试。
9. **财务与健康数据不删除**，只作废/匿名化；访问要留痕。取消/作废的单据不计入营业额统计报表。
10. **状态托管，应用无状态**：不自管 Postgres、不自管 Redis Pub/Sub、不自建 WebSocket 扇出。
    **任何"需要在应用节点之间同步状态"的设计都是错的** —— 那说明状态放错了地方。
11. **UI 面向"英文不好、四十岁以上、戴着手套"的用户设计**：大按钮（≥56px）、大字、图标优先、声音+震动提醒。
12. **Desk 端必须键盘可完成高频操作**（搜客人、开单、结账、叫号），与大按钮双轨并存；
    **危险操作（作废/退款/删除）永不绑快捷键**。Staff / Kiosk 端不设任何快捷键。
13. **短信不阻塞任何业务流**。门店数 ≥ 10 家之前，代码里不写任何短信依赖，所有通知走 Web/邮件/前台回呼。
14. **系统必须在仅有前台单端（Desk-Only）的情况下 100% 独立流畅运行**，绝不对 Staff 手机端或 Kiosk 产生强依赖/阻断卡点。
15. **约束分层**：物理资源（房间/床/椅）是数据库硬约束；技师并发与门店容量是应用层软告警，可覆盖但必须记原因。
    **永远不给 `membership_id` 建排他约束。**
16. **客户的唯一凭证是 `customers.id`**，手机号只是查找键。同号多客户必须走选择器，默认不自动匹配。
17. **审计留动作不留金额**：ticket / payment 的金额字段不写入 `audit_log` 的 before/after。
18. **断网时页面不遮罩、不关闭**：切只读看板 + 顶部横幅 + 写操作置灰。**永不做离线写入队列。**
19. **每期结束必须能被一家真店从早用到晚**，否则不算完成。
