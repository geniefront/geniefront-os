# AI 语音预约套餐 V1 改造计划

日期：2026-09-19。状态：V1 核心已在 staging 实施及联调；详细完成项和限制见 `../integrations/voice-booking-v1.md`。以本次用户确认的产品范围和计费规则为准。

## 1. 已确认的目标

- 新增正式套餐 `voice_booking`，共用现有应用与后端；现有 Essential / Growth 继续保留完整版能力。
- 预约版只允许切换到 $199/月的 Growth，不允许切换到 Essential；店家入口、运营后台与后端统一执行。
- 保持现有 UI 的布局风格、配色、组件、预约操作方式与响应式适配，通过减少入口和字段精简体验。
- 保留预约增删查改、客户信息、AI 语音、录音、transcript、短信及 Email 通知。
- 不提供排班、轮牌、营销、健康表、收银、工资提成等完整门店经营功能。
- 网站和语音由运营方 setup，后端提供 API、接入配置、记录、通知与计量。
- 电话号码、电话线路与录音使用 Telnyx；实时 AI 客服使用 xAI；通话结束后由后端取得 Telnyx 录音，交给 xAI 转录。此链路作为独立开发项，不能假设已完成。
- 运营可不经 Stripe 开账号、设服务截止日期和基础额度，再交付店家绑定付款方式。
- 骚扰、持续无效静音、推销、系统故障、无关闲聊不扣客户额度；预约意向及门店业务咨询照常计入，不取决于预约成功。
- 单通电话硬上限 10 分钟。
- 套餐切换、付款模式切换、切店、刷新与重新登录后，功能与订阅显示必须一致。

当前官网的 $99 / 200 语音分钟作为预约版初始配置，不在本轮计划中重新定价。

## 2. 代码现状与必须修正的缺口

以下为实施前发现的问题，保留用于追踪；当前验证结果见接入说明。

- `apps/marketing/src/lib/plans.ts` 已包含预约版，部分 signup / Stripe Checkout 路径也已接受它。
- `packages/payroll/src/credits.ts` 的正式 Plan 仍只有 essential / growth；未知套餐会回退到 Essential 额度。
- `apps/web/src/features/billing/display.ts` 的名称、徽标和 canonical plan 也只识别上述两档。
- `apps/api/src/queries/billing.ts` 已返回付款来源、有效期、绑卡和额度状态，但应统一当前权益、待生效变更和额度周期的口径。
- 已有 license 运营开店、有效期调整和额度补充路径，应复用并完善，不再新造一套人工计费系统。
- 已有预约、电话记录、转录补拉和通知基础；录音可靠获取与完整通知闭环需要专门验收。
- 当前 `apps/api/src/telnyx/conversations.ts` 从 Telnyx AI Assistant conversations/messages 读取转录，`reconcile.ts` 依赖这条补拉路径；它不是 xAI 录音转录。
- 本轮检查 apps、packages、scripts 及环境变量示例，没有找到 xAI API 客户端、实时客服会话或录音提交 xAI 的实现。未检查线上控制台，不能据此断言外部账号也没有配置。
- `apps/api/src/telnyx/routes.ts` 现有 webhook 在处理短信后只接受 call.hangup，其余事件被忽略，尚无录音完成事件处理。数据库已有 recording_url 字段，不代表录音获取和归档链路已打通。
- 现有日程和开店流程包含员工、资源及排班语义，需要让预约版在没有员工班表的情况下独立运行。

预约版为 200 分钟，唯一可切换目标 Growth 为 $199/月、500 分钟。Essential 的 60 分钟配置仍服务其现有套餐，但不作为预约版的切换选项。功能和额度必须按正式套餐定义读取。

### 3.1 保留现有页面，按套餐减少内容

| 区域 | 预约版展示 |
| --- | --- |
| 首页 | 今日预约、待处理来电、通知失败、语音剩余额度；移除营收、工资、轮牌等卡片 |
| 预约 | 现有日历、列表和预约抽屉；新增、查询、修改、取消、完成、未到店 |

| 通知 | 预约和通话通知的发送状态、失败及重试记录 |
| 设置 | 门店、服务及时长、营业时间、预约容量、接收通知的号码和 Email、订阅与额度 |

覆盖侧栏、移动导航、首页快捷入口、命令搜索、设置页签、客户详情、预约抽屉、空态引导与开店向导，避免菜单隐藏后还残留入口或必填项。

套餐限制同时落实到后端 API 和前端路由，不能只隐藏按钮。最终权限为用户角色权限与门店套餐能力的交集。

### 3.2 无排班预约

- 保留服务项目、服务时长、营业时间、时区、休息日、临时封锁时段、预约提前量与同时间接待容量。
- 无需创建员工或排班即可开通；按完整服务区间检查容量，创建与改期具备并发保护。
- 保持现有日历视觉与交互，预约版采用门店预约视图，不依赖技师列才能显示预约。
- 取消留历史与审计，不以物理删除作为日常操作。
- 完整版切换到预约版时，已有未来预约继续显示并占容量；员工关联保留为历史信息，不因功能关闭而消失。
- 无排班模式的容量配置应在切换前预览；切换不会重新分配、取消或重建已有预约。

## 4. API、通话资料与通知

- 网站与语音复用服务、可约时段、预约创建、详情、改期和取消能力；店家后台具备完整预约 CRUD。
- 网站客人及语音对既有预约的查询、改期、取消需验证归属；不能只凭来电号码访问或操作客户历史。
- 现有语音查空位和新建先完成闭环；语音改期、取消在身份验证路径可用后启用。
- 按下述 4.1 接入 Telnyx + xAI；复用现有预约和通知业务逻辑，替换对 Telnyx AI Assistant 作为客服及转录来源的依赖。
- 后端完成 webhook 验证、可信门店映射、去重、状态更新、资料补拉和失败重试。
- 预约成功立即发店家通知，不等待录音和 transcript；通话结束后异步归档资料、生成摘要及关联预约。
- Email 提供业务信息、摘要与详情链接；SMS 提供简短结果与详情链接。录音和全文在授权页面查看。
- 录音访问受门店权限控制，明确保存期限与链接有效期。
- 短信、Email 的业务通知与语音分钟分开计量；预约版不能因为 AI credits 为 0 而无法通知。
- 第一版通知按套餐内业务通知处理，内部保留条数、分段、成本和异常发送限制；不开放营销群发。
- 官网“无限员工日历”等与精简版不符的文案同步修正，通知额度与公平使用说明保持一致。

### 4.1 Telnyx 号码与录音 + xAI 客服与转录（新增独立工作项）

目标链路分为两条，录音转录不阻塞实时预约：

```text
实时：客人 → Telnyx 号码/线路 → xAI 语音客服 ↔ 后端预约工具 → 预约落库及通知
事后：Telnyx 录音准备完成 → 后端按录音 ID 获取 → xAI 转录 → 通话详情、摘要、计费判定及店家通知
```

**先做真实电话技术验证。** xAI 当前官方文档已有 Telnyx SIP 接入说明，优先验证该路径。验证同一呼叫能否同时满足 Telnyx 完整录音、可信门店映射、后端工具调用、转人工和 600 秒强制结束；SIP 路由能接通不代表录音及控制能力自动可用。若直连无法同时满足要求，再评估 Telnyx Call Control 配合实时媒体桥接，不在验证前锁死实现方式。

1. **Telnyx 接入与录音**：号码绑定门店，配置线路与录音，接收并验签录音完成事件；按最终选择的 SIP / Call Control 路径确认事件和控制接口。使用稳定的 call/session/recording 标识关联记录，录音未生成、链接过期、事件遗漏均有补偿任务。优先验证双声道，确保顾客和 AI 双方声音都录到，并保留现有开场录音告知。
2. **xAI 实时客服**：建立门店对应的语音会话，加载运营设置的语言、音色、话术、服务资料和工具；处理接听、打断、超时、结束、异常及转人工。API 密钥由服务端管理。需要长连接时明确会话归属、断线处理、部署排空和 10 分钟控制，更新原先基于 Telnyx 托管 assistant 的无长连接架构说明。
3. **预约工具适配**：复用后端查服务、查空位、创建预约等业务能力，新增 xAI 工具调用适配。租户上下文由已验证的通话绑定确定，不信任模型自行传来的门店 ID。工具调用幂等，只有后端实际成功后 AI 才能确认已预约。
4. **录音交给 xAI 转录**：Telnyx 保存录音后由后端获取音频并异步提交转录接口，保存全文、可用的时间戳、语言及说话人信息。实测文件格式、长度限制和声道语义；接口不提供的角色或时间戳不能编造，必要时按声道拆分。转录任务支持重试、去重、失败复核。
5. **区分实时记录和最终转录**：实时对话事件、工具执行结果与事后录音转录分别保存，UI 标示处理中/完成/失败。最终转录用于阅读、摘要及辅助计费审查，不重新执行预约命令，也不覆盖预约真实结果；预约和故障事实以业务事件为准。
6. **替换旧补拉与计费**：新链路不再依赖 Telnyx AI conversations；按通话供应商/处理模式选择补偿任务，避免旧 reconcile 和新任务重复记录、重复扣费。旧挂断即结算逻辑改成先记录实际用量，再按已确认的免费规则结算。
7. **运营 setup 交付**：你负责号码、网站、门店话术/音色与资料设置；后端提供受控配置入口、回调地址、工具协议、接入状态与测试流程。店家端不新增复杂 AI 配置页。
8. **成本核对**：分别记录 Telnyx 线路与录音、xAI 实时语音、xAI 事后转录、短信和 Email 成本。$0.088/分钟先作为测算假设，真实电话验证后确认是否已包含额外转录、录音及必要的多路通话费用，不把两次处理误计为一次供应商成本。

文档依据（2026-09-19 检查）：[xAI SIP 电话接入及 Telnyx 配置](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech/sip)、[xAI 音频文件与流式转录](https://docs.x.ai/developers/model-capabilities/audio/speech-to-text)、[Telnyx 录音停止及完成事件](https://developers.telnyx.com/api-reference/call-commands/recording-stop)。具体能力以选定线路的实测为准。

## 5. 语音计费规则

| 类型 | 客户额度处理 |
| --- | --- |
| 预约、查空位、改期、取消 | 计入 |
| 价格、服务、地址、营业时间等业务咨询 | 计入 |
| 店满、价格不合适、客人主动放弃 | 计入 |
| 骚扰、推销、无关闲聊 | 豁免对应时段 |
| 持续静音且没有有效交流 | 豁免对应时段 |
| 平台 AI / 系统故障导致无法服务 | 豁免或冲销；影响整通则整通返还 |

- 正常交流中的短暂停顿属于业务通话时间。
- 混合通话根据阶段时间戳记录业务与豁免时段，不因一句闲聊把整通业务电话免掉。
- 整通最长 600 秒，由供应商通话控制及后端兜底落实，不能仅靠 prompt。第 9 分钟提示，未完成则留下回电请求；AI 不能声称未落库的预约已成功。
- 静音、推销、闲聊提前引导结束，避免都消耗到 10 分钟。
- 每通保存原始秒数、可计费秒数、豁免秒数、原因、判定依据和规则版本。
- 初版建议延续每通向上取整到分钟的口径：先合计该通可计费秒数，再统一取整一次；不逐片段取整。全部豁免为 0，并在 UI 说明。
- 判定结合业务事件、工具执行结果与转录分类；模型结论不能直接修改余额。故障免计费不能只依赖模型自报。
- 资料尚未到齐时显示“计费待确认”；挂断时先记录供应商用量，分类完成后结算一次。资料缺失超时进入待复核，不能永久挂起或自动判成全额收费。
- 通话中预留额度，结算后释放豁免部分，防止并发通话超用；跨续费或套餐切换的通话关联明确的额度周期。
- 结算、补拉、重复 webhook、人工返还均幂等；返还以追加冲销记录实现，不覆盖历史账本。
- 每店免费用量预算先用于内部提醒和异常处置，不得触发暗中向店家收费。若要限制免费服务，必须明确告知后生效。

## 6. 人工开通与后绑定付款

运营流程：创建门店和店主 → 选套餐 → 设置有效截止日期及基础额度 → 配置网站与语音 → 交付登录账号 → 店家绑定付款方式或选择自动续费。

运营后台提供套餐、付款模式、有效期、额度周期、基础额度、赠送额度、延期、暂停、恢复及操作原因。

- 复用现有 license 计费来源，UI 面向用户显示“人工开通 / 线下付款”。
- 不要求店家先开 Stripe 商户账户；这里绑定的是用于支付平台订阅的付款方式。
- 绑卡状态、自动续费安排、当前服务权益三者分开；绑卡成功不会自行改变套餐、发额度或提前扣费。
- 建议保留人工给出的有效期，店家明确启用自动续费后从约定日期开始收费；后端保存待生效状态。
- 有效期与额度周期分开；延长截止日期不重复发额度，也不擅自归零已用额度。
- 到期仍能登录、查看历史和续费；停止新增预约和新的付费语音使用，已产生的通话资料与通知任务完成收尾。
- Stripe → 人工模式必须先确认停止该门店未来收费，保留历史，失败显示待处理；不能误停同组织其他门店。
- 人工 → Stripe 在明确授权的订阅安排生效后交接计费权威；旧订阅事件不得覆盖人工权益。

## 7. 订阅切换与显示一致性（重点验收）

### 7.1 单一权益来源

后端统一返回当前套餐、当前功能、付款来源、服务有效期、额度周期、基础额度、已用量、赠送/充值余额、绑卡状态及待生效套餐和日期。前端菜单、路由、套餐徽标和订阅页使用同一份有效权益。

不得按是否存在历史 Stripe ID 推断当前付款模式，不得把未知套餐静默显示为 Essential。

### 7.2 切换规则（计划默认值）

- 预约版唯一可切换目标为 Growth（$199/月）；续订原预约版和切换付款模式不属于套餐变更，不受此限制。
- UI 只提供 Growth 升级入口；运营变更、API、Checkout 和 Stripe Portal 可选项统一限制，不能通过直达链接绕过。收到不允许的外部套餐变更时进入异常处理，不静默授予错误权益或忽略已发生的收费。
- 自助套餐变更默认下期生效，展示“当前套餐 / 下期套餐 / 生效日期”；待生效期间保留当前权益。
- 运营支持立即变更，提交前显示变更后的功能、有效期及额度；已付账期的补差或退款必须明确，不能只改本地套餐。
- 同一额度周期立即变更：不清零已用量，不重复发完整套餐额度；根据目标额度及运营覆盖值重新计算剩余，最低显示 0。
- 示例：本期已用 100 分钟，从 200 分钟预约版立即改成 500 分钟 Growth，基础剩余为 400 分钟，不再额外发放一整份 500 分钟。额度调整另留记录，充值与赠送余额不丢失。
- 新周期只发放一次新周期额度；重复 webhook 或页面刷新不会再次发放。
- 从完整版降到预约版，隐藏相关功能，保留客户、预约和其他历史数据；再次升级后恢复可见。
- 降级时停止该套餐不再允许的后台营销、健康表邀约等自动任务，不能只隐藏页面。

### 7.3 页面状态

| 状态 | 必须展示 |
| --- | --- |
| 人工开通、未绑卡 | 当前套餐、有效至日期、额度、绑定付款方式入口；不显示不存在的下次扣款 |
| 已绑卡、尚未启用续费 | 付款方式已绑定；明确未开启自动续费，当前有效期保持原值 |
| 已安排后续订阅 | 当前权益与未来套餐/收费日期同时可见 |
