# 00 · 行业发掘（美国 Spa / Nail / Massage / Foot Spa 门店运营）

> 目的：把「我也不知道我具体需要什么」变成一份可以打勾的清单。
> 下面每一条都是美国实体店真实存在的运营动作。**打 ⭐ 的是你原始需求里没提、但会决定产品成败的**。

---

## 1. 前台端（Front Desk）——真实的一天

美国这类店的前台不是"接电话的"，是**调度员 + 收银 + 合规员 + 客服**四合一。按一天的时间线拆：

### 1.1 开店前
- 核对今日排班（谁请假了、谁迟到、谁换班），临时补人
- 现金抽屉起始金额（starting drawer / float），点钞留档 ⭐
- 打印/查看今日预约表，标出 VIP、新客、需要特殊准备的（孕妇、过敏、指定房间）
- 房间/床位/椅子准备状态（清洁完成、设备正常）⭐

### 1.2 营业中——排队与轮牌（这是你说的"排班方式很复杂"的真正内核）⭐⭐⭐

美国 nail/foot spa 主要有 **三套并行的分配逻辑**，同一家店往往同时跑：

| 模式 | 英文 | 说明 | 数据要求 |
|---|---|---|---|
| **轮牌 / 排钟** | Turn rotation | 技师排成一个圈，walk-in 客人按顺序轮。做完一单回到队尾 | 需要 `turn_order` 队列 + 每单消耗的"turn 值" |
| **点钟 / 指定** | Request | 客人指名技师。多数店规定：**指名单不占轮次**（不消耗 turn），有的店指名要加钱、技师抽成更高 | `is_request` 标记 + 是否计入轮次的策略开关 |
| **预约优先** | Booked | 有预约的技师到点被"锁住"，轮牌自动跳过他 | 轮牌引擎必须读预约表 |

**轮牌里必须支持的细节（几乎所有现成软件做不好的地方）：**
- **半轮 / 整轮**：一个 $25 的修甲算 0.5 turn，一个 $80 的套餐算 1 turn，或者按金额/时长折算。**规则必须店主可配**
- **跳过（skip）**：技师不会做这个项目（不会做美睫/不会做深层按摩）→ 自动跳过且**不算他一轮**
- **强制跳过**：技师在吃饭/请假/上厕所 → 临时 off-rotation，回来后插回队列哪个位置（队首？原位？队尾？）也要可配
- **欠轮 / 补轮**：被跳过的人下次优先
- **Turn board 可视化与前台绝对裁决权**：一块大屏/平板，所有人都能看到"现在轮到谁"，减少吵架 ⭐。**前台拥有最终裁决权**：支持直接拖拽调整轮牌顺序、手动插单或强制指定技师。每次手动干预强制选择简易原因（如"客人指定/技师暂休/前台协调"），系统记录完整不可篡改的事件流水，彻底消除技师对前台"偏心"的猜忌。
- **一人多角色（店长 / 前台 / 老板自己也接客）** ⭐：非常普遍，必须拆成两个独立开关——**是否可被排单**（出现在日程表列里）与**是否参与今天的 walk-in 轮牌**。最常见的组合是**店长可接点钟单但不吃 walk-in 轮**；老板则是人手不够时当天临时下场。所以"参与轮牌"必须按**营业日**存，不是按角色存。

### 按摩/足疗店还有：
- 男/女技师偏好（客人明确要求）⭐ — 必须是可筛选字段
- 技师语言（中文/韩语/越南语/西班牙语/英语）匹配客人 ⭐
- 双人房 / 情侣按摩：**需要同时锁 2 个技师 + 1 个双人房**，这是一个"复合资源约束"，不是简单的两条预约

### 1.3 Walk-in 与等位 ⭐
- Walk-in 排队 + **报等待时间**（"大约 25 分钟"），系统应能根据当前在做的单子剩余时间自动估算
- 叫号机制（短信上线前通过现场屏幕/声音叫号，短信上线后发短信）
- **Waitlist（候补）**：客人想要周六下午但满了 → 登记候补，一旦有人取消自动通知（这是白捡的营收）
- 客人放弃排队要记录（流失分析）

### 1.4 客人到店
- 签到（前台点 / 客人自助 iPad kiosk 扫码签到）⭐ — kiosk 是**第四个端**，你只规划了 3 个
- **健康表 / 知情同意书（Intake & Consent）**：
  - 按摩类在美国是**法律与保险刚需**：禁忌症问卷（怀孕、高血压、近期手术、血栓、皮肤病）、责任免除（waiver）、遮盖同意（draping consent）
  - 未成年人需监护人签字 ⭐
  - 必须：**版本化模板 + 电子签名 + 时间戳 + IP + 不可篡改留档**（出事时这是唯一证据）
  - 多语言版本（同一份表要有 en/zh/ko/vi/es 五个语言版本，签的是同一份法律文件）
  - 有效期：一般 6–12 个月复签一次，或每次简版复核
- 老客直接带出上次的偏好、指甲照片、备注、过敏
- **落单要素（每个业态不一样，必须在开单时问清）** ⭐⭐：按摩要问**力度 + 重点部位 + 避开部位**，美甲要问**做法/甲型/长度/色号/是否卸甲**，头疗要问**头皮类型 + 力度 + 染烫史**，美睫要问**类型/卷翘/粗细 + 胶水是否过敏**。这些不是"备注"，是决定时长、价格、提成和客人满不满意的结构化字段。做法见 `02` §3.1 —— 一套 `service_option_defs` 机制按业态出预设，老客的选择 sticky 回填（"跟上次一样"就是一个按钮）

### 1.5 服务中（动态变更与极端场景）
- 技师端点「开始 / 完成」→ 前台实时看到（或由前台单端代点）
- **加钟 / 加项（upsell）**：技师在手机端点加项，或口头报前台，前台账单实时追加 Add-on / 延长工时，结账时自动计入提成 ⭐
- 房间清洁状态流转：占用 → 待清洁 → 可用 ⭐
- 重叠服务：美甲师给 A 客人做手部时，B 客人的脚在泡水/等干 → **一个技师同一时间段可以合法地压两单**（processing time / overlap booking）⭐

### 1.5.1 极端/复杂/不常见业务场景处理规范 ⭐⭐⭐

在亚裔服务业日常运营中，以下复杂与极端情况屡见不鲜，系统在底层模型与交互上已完全支持：

| 极端/动态场景 | 现实业务痛点 | 系统应对与算法处理方案 |
|---|---|---|
| **1. 中途换技师 / 接力服务**<br>*(Mid-Service Relay)* | 技师 A 做了前 30min 基础打底，被 VIP 点钟叫走；技师 B 接手后 40min 做复杂彩绘 | • **单项拆分/接力记录**：账单支持将该项目关联到多个技师，记录每人实际工时（如 Amy 30m，Kim 40m）或自定义权重分配。<br>• **提成与小费**：系统按各自贡献工时/比例自动拆分提成与小费。<br>• **轮牌扣减**：前台可选择给 Amy 记 0.5 轮，Kim 记 0.5 轮，或全记在主技师身上。 |
| **2. 中途更换项目**<br>*(Mid-Service Swap)* | 客人原本约 $35 基础修甲(30m)，坐下后临时改做 $95 延长光疗(80m) | • **一键改单**：前台或技师点击“更换项目”，系统自动替换单价与时长。<br>• **排期联动告警**：若技师后面已约了下一位客人，系统立即高亮提示：*“Amy 下午 3:00 有预约冲突，建议将后续单顺延 30min 或一键改派给空闲的 Linh”*。 |
| **3. 多人同行合单与拆单**<br>*(Party Merge & Split)* | 母女/闺蜜 3 人同行，可能一起结账，也可能中途突然说各自付，或 A 付服务费、B 付小费 | • **动态合单/拆单**：前台支持一键勾选多个正在进行的工单“合并结账”，或将一个多项目工单“拆分成独立账单”。<br>• **混合小费支付**：支持 A 刷卡付全部服务费，B 拿现金单独付某位技师的小费。 |
| **4. 双技师/多技师同时做一人**<br>*(Dual-Tech / 4-Hand)* | 两个人同时做：Amy 做手、Linh 做脚，或者双人四手按摩 | • 一个预约项同时绑定 2 名技师与 1 个工位。<br>• 薪酬引擎自动按各自项目单价或时长权重拆分提成。 |
| **5. 客人走单 / 拒付 / 坏账**<br>*(Walk-Out / Bad Debt)* | 客人做完借故上厕所跑单，或信用卡反复被拒离店 | • **作废并标坏账**：前台作废单据并选择 `cancel_reason: 'walk_out'`，强制输入事件备注并记录黑名单。<br>• **技师提成保护开关**：店主配置 `protect_tech_commission_on_bad_debt`（即使单子没收到钱，老板依然给技师发该单的基础提成，保障员工权益）。 |
| **6. 跨营业日通宵单**<br>*(Overnight Day Cutoff)* | 足疗/按摩店开到凌晨 2:00 或 4:00，跨过了 00:00 | • 系统引入 `business_day_cutoff`（如设定为 `03:00`）。凌晨 1:30 开的单依然归入**昨天的营业日**，打烊日结和小费发放不会被切成两天。 |
| **7. 技师突发意外离场**<br>*(Tech Emergency Exit)* | 技师做到一半切到手指或身体突发不适无法继续 | • 前台一键操作“紧急交接”：将当前进行中的单据暂停并改派给备用技师，已完成部分锁定 Amy 的提成，后续部分由新技师接替。 |
| **8. 结账后反悔 / 小费重分配**<br>*(Post-Checkout Tip Adjustment)* | 前台收银时输错，把 $20 小费全给了 Amy，客人走后提醒其实是想给 Amy $10、助理 Linh $10 | • 在日结（Daily Close）关账前，前台/店长拥有 **“小费分配纠错权限”**，重新调整分配比例，系统自动更新 `tip_allocations` 并产生审计日志，无需刷退信用卡。 |

- 服务在多数州**不收销售税**，零售商品（指甲油、精油）**收税** → 税率按 location 配置 ⭐
- 支付方式混合：现金 + 刷卡 + 礼品卡 + 套餐次数 + 积分，一单可能拆 3 种
- **小费（Tip）**：见下面第 3 节，单独讲
- 折扣、优惠券、Groupon/Yelp 团购核销 ⭐（团购券的实收金额 ≠ 面值，财务要分开记）
- 退款 / 作废（void）→ **必须权限 + 留痕**，这是老板防内盗的核心
- **薪酬计算与分配明细 (Settlement Helper)** ⭐：很多门店使用第三方账本或需要单独向老板汇报薪资。结账页在**选定支付方式之前**就实时显示该单的提成与小费分配结果，并提供「一键复制分配明细」。
  - **顾客付现金还是刷卡，往往要到结账那一刻才知道**，所以「开单 → 加项/加钟 → 结账」这条流程必须完整走完，不能跳。
  - 结账页选定支付方式后有两条出口：**正常入账**（进营业额与报表）或 **作废**（必选原因 + 备注，记录保留但不计入营业额与日结）。
  - `audit_log` 对工单只留动作不留金额（见 `02` §8）。**不做取消率异常监控。**
  - **复制文本格式规范（针对微信聊天窗口优化）**：用 emoji 分隔，不用 HTML，确保在微信/iMessage 里显示整齐。示例：`📋 #1041 | 8/14 15:30 / 💇 Amy - 全身按摩 60min / 提成: $60 / 小费: $12`
- **礼品卡（Gift Card）**：美国 spa 的巨大营收来源（尤其节日）。法律上：联邦 CARD Act 要求至少 5 年有效期；加州禁止设过期日、余额低于 $10 可要求兑现金；未兑付余额还涉及各州 escheat（无人认领财产）申报 ⭐⭐ 这些不做对会被罚
- **套餐 / 次卡 / 会员月费**（Massage Envy 模式：月付 $79 存一次按摩，可累积、可转让）⭐ 这是提高客户 LTV 的最强武器
- 忠诚积分

### 1.7 关店
- **日结（Daily Close）**：点钞、现金进出（买物料的零钱）、账实差异记录、存款单 ⭐
- **外部刷卡终端日结比对**：前台手动录入物理刷卡机（Clover/Square Terminal）的日结汇总金额，系统自动与内部信用卡记录比对，高亮差异（Variance），强制补单或说明原因后方可关账 ⭐
- 当日现金小费发放（很多店当天发现金小费给技师，要从抽屉扣）⭐
  **现金小费发放工作流（每日打烊仪式）**：老板打开“今日现金小费汇总”页面 → 系统显示每个技师今天应得的现金小费总额 → 老板从钱箱里数钱逐人发放 → 技师点“已收到”或老板代为确认 → 系统更新 `cash_tip_payouts` 表。这是每天打烊时最重要也最容易吵架的环节，**必须做成独立 UI 模块** ⭐⭐
- 技师当日业绩单（很多技师下班要看自己今天做了多少）
- 交接班备注（早班给晚班留话）⭐

### 1.8 电话 & 通讯 ⭐
- **AI 电话识别（聚焦三要素）**：
  - 来电号码自动匹配客户档案（Caller ID）
  - 核心提取三要素：想做项目、指定技师/偏好、期望时间/要求
  - 自动查空档生成草案，推送到前台复核队列（前台 1 秒确认/微调）
  - 听不清或复杂诉求自动生成待办工单，前台一键回拨
- **短信解耦（独立专项期上线）**：10DLC 批准前，前置阶段不阻塞业务流（通过邮件、页面链接、前台回呼降级）；10DLC 通过后启用自动确认、24h/2h 提醒、叫号、唤醒。

### 1.9 前台还需要但你没提的
- **No-show / 迟到政策**：系统记录历史爽约次数，但在前台弹窗**高亮预警即可（由前台人工决定是否接待）**，避免死板的“自动拉黑”误杀因故迟到/临时取消的高净值老客。具体展示：当前台为该客户创建预约或签到时，若 `no_show_count >= 2`，在客户姓名旁显示醒目 Badge（如 🔴 `No-show x3`），点击可查看历史记录，**不阻断操作流程**；留卡担保（card on file）/ 定金；按摩类客单价高，不做定金会被爽约打死 ⭐
- **黑名单 / 安全事件记录**：按摩行业存在客人不当行为，需要记录 + 一键报警按钮（技师端）⭐⭐ 这是员工安全底线，做了会被门店记住
- **卫生消毒记录**：多州（如加州）对足浴盆清洗消毒有强制记录留存要求，检查员会当场查。做成 App 里的每日打勾 + 留档，是**监管刚需 + 差异化卖点** ⭐⭐
- **执照到期跟踪**：技师的州执照、店铺执照、保险到期提醒 ⭐
- 忙时/节假日加价（美国 nail 店节日普遍加 $5–$10 holiday surcharge）⭐
- 按技师等级定价（Level 1 / 2 / Master 同一项目不同价）⭐
- 客人指甲照片、样式参考图（要有客人肖像/作品使用同意）

## 2. 员工端（技师）——实时触达与极简交互

技师群体：40–60 岁为主、英文不好、戴着手套、店里嘈杂。

- **网页端/PWA 实时长连接与感知**：
  - 保持 **Supabase Realtime WebSocket 长连接**
  - **声音提醒（Web Audio API）**：新单到达播放专属清脆提示音（"叮！新客人"）
  - **物理震动（Vibration API）**：装在口袋里的手机产生短震动
  - **全屏高亮翻转卡片**：直接展示下一位客人姓名、项目、座位号，戴手套扫一眼即懂
  - **切后台/锁屏唤醒补偿**：监听 `visibilitychange` 事件，技师点亮屏幕切回浏览器瞬间，自动触发轻量增量对齐，0.5 秒内刷出最新任务
- **登录方式**：很多技师不用邮箱、英文不好。**必须支持共享 iPad 上 4 位 PIN 打卡** + 个人手机号 OTP 登录两套 ⭐
- 防代打卡：打卡拍照 / 绑定门店 Wi-Fi / 地理围栏 ⭐
- **我的收入看板**：今日/本周 服务提成 + 小费，实时跳动。技师最关心这个，是留存的关键
- **排班相关**
  - 可用性偏好（我周二不上班）vs 实际排班（店长排）——两张表，别混
  - **换班申请 / 互相调班**，需要审批流 ⭐
  - 排班发布 + **员工确认已读**（劳资纠纷时有用）⭐
  - 加班预警（接近 40 小时提醒店长）⭐
- **下一位客人卡片**：姓名、**脱敏手机号（如 917-***-1234，防私挖老客）**、项目、备注、上次做的样式、语言、是否指定我，以及**本单的落单要素**（力度、重点部位、甲型色号…，即 `to_staff = true` 的项）。**避开部位 / 过敏 / 胶水敏感红底高亮置顶**——这是技师戴着手套扫一眼最需要看到的东西（`02` §3.3）
- **状态自报**：可接客 / 服务中 / 休息 / 请假 → 前台的轮牌板实时更新
- 加钟/加项按钮（回到 1.5）
- **休息申请**（"我想歇一轮"）→ 前台批 → 轮牌自动跳过
- 一键求助 / 紧急按钮 ⭐
- 我的执照到期提醒、培训记录
- 界面语言：技师端**必须**是越南语/韩语/中文/西班牙语可切，且是**按人**设置不是按店 ⭐

## 3. 薪酬与小费引擎（技师等级差异化与分配规则）⭐⭐⭐

这是实体店管理中最核心也最容易产生人事摩擦的部分。系统已建立**“技师等级三维差异化矩阵（3D Level Matrix）”**：

### 3.0 技师等级的三维差异化体系
技师分为不同职级（如：`Junior / Level 1 / Senior / Master / Director`），在系统中有三个维度的独立配置：

| 维度 | 业务含义 | 示例配置 |
|---|---|---|
| **1. 项目定价差异化**<br>*(Price Modifier)* | 高级别技师同一项目收取更高服务费 | 普通美甲师基础光疗 $45；Master 资深美甲师基础光疗 $65 |
| **2. 服务提成比例差异化**<br>*(Commission Rate)* | 高级别技师享有更高百分比或阶梯抽成 | 学徒/新手提成 40% (4000 bp)；普通大工提成 50% (5000 bp)；总监级提成 60% (6000 bp) |
| **3. 小费分摊加权系数**<br>*(Tip Weight in Multi-Tech)* | 多人合作/双人/接力服务时，小费按等级系数加权计算 | Master 权重 1.5x (15000 bp)；Senior 1.2x；普通技师 1.0x；助理/洗头工 0.5x |

**多人服务小费计算透明示例**：
> 一单 $30 小费，由 Master 技师 Amy（权重 1.5，做了 40min）与 新手技师 Kim（权重 1.0，做了 40min）合作完成：
> - 综合权重分：Amy = \( 1.5 \times 40 = 60 \)；Kim = \( 1.0 \times 40 = 40 \)
> - Amy 分得：\( \frac{60}{60+40} \times \$30 = \mathbf{\$18.00} \)
> - Kim 分得：\( \frac{40}{60+40} \times \$30 = \mathbf{\$12.00} \)
> - 系统将计算依据 `{ "rule": "level_and_duration", "amy_weight": 1.5, "kim_weight": 1.0 }` 存入数据库，技师下班查看明细一清二楚。

### 3.1 分配维度（规则引擎支持的输入）
- 服务时长占比 / 服务金额占比 / 平均分 / 按技师等级加权 / 按角色加权（主技师 vs 助理）
- 双技师服务：按各自实际服务时长 × 等级系数
- 前台/助理的 tip-out（技师按比例分给洗头工、助理）
- 现金小费 vs 刷卡小费分别处理（现金当天发，刷卡进工资）
- 取整规则、余数归谁
- **必须有"模拟/预演"模式**：店主改规则前先跑一遍上周数据看结果差异，否则没人敢改

### 3.2 法律护栏（这些必须写进产品，否则你会成为违法帮凶）
- 联邦 FLSA（2018 修正）：**雇主、经理、主管不得占有任何小费**，即使不使用 tip credit。→ 产品里"店铺抽成小费"这个选项要么禁用，要么强警告 ⭐⭐
- 小费池包含非小费岗位（如后厨/清洁）仅在**不使用 tip credit** 时允许
- **强制服务费（service charge）在法律上不是小费**，属于营业收入/工资，税务和分配规则完全不同 → 数据模型里 `tip` 和 `service_charge` 必须是两个字段 ⭐⭐
- 加州：无 tip credit，**无论提成多少都必须保底到最低工资**；提成协议须书面签署；第 5 小时前必须给 30 分钟无薪餐休；有 split shift 补贴
- 抽成 vs 租椅（booth rent）：租椅是 1099 独立承包商，**排班/小费/工资规则完全不同**（加州 AB5 对持照美容师有条件豁免）→ 数据模型必须支持一家店里同时有 W-2 员工和 1099 租椅者 ⭐⭐

> 建议：产品内的所有薪酬/小费配置页面都加一句"请与您的会计/劳动法顾问确认"，并保留完整审计日志。这既是保护客户也是保护你自己。

## 4. 老板端

- 实时看板：今日营收 / 客流 / 平均客单 / 各技师产值 / 房间利用率
- 对比：同比环比、上周同一天
- **异常告警**（防内盗，老板最想要）：折扣率异常、作废单异常、现金差异、某技师无小费单占比异常 ⭐
- 人力成本率（工资+提成+小费 ÷ 营收）
- 客户分析：新客/回头客比、**复购间隔**、流失预警（"85 个客人 60 天没来了，一键发召回短信"）⭐
- 预约密度热力图 → 指导排班
- 零售连带率
- 多店对比（连锁）⭐
- 订阅/账单（你说交给别的 AI，但**门店内要有入口看账单和用量**）

分三层，别混为一谈：

1. **AI 前台副驾（打字/说话操作系统）**——你的主诉求
   - "给 Amy 明天下午 3 点排一个 60 分钟深层按摩，客人叫 Lisa 917-xxx"

## 6. 多语言（比你想的更细）

- **界面语言按"人"**（每个员工各自选），不是按店
- **顾客沟通语言按"顾客"**（给越南阿姨发越南语提醒短信）
- **店主自建内容（项目名、描述）需要多语言字段**，缺失时回退到店铺默认语言 → 建议 `jsonb` 存 `{en: "...", vi: "..."}`，配 AI 一键翻译
- 首批语言：`en` `zh-Hans` `zh-Hant` `ko` `vi` `es`
- 姓名/地址格式、日期（美国 M/D/Y）、12 小时制、电话格式统一 E.164
- **时区**：全美多时区 + 夏令时。所有时间存 `timestamptz`，但排班/营业时间必须按门店本地"墙上时间"计算；营业日边界（凌晨 2 点关门算前一天）要单独定义 ⭐

## 7. 合规与隐私（美国市场必须提前设计，事后补极痛）

- **健康问卷属敏感个人信息**：单独加密存储、按权限最小化访问、访问也要审计（一般 spa 不属于 HIPAA covered entity，但按敏感数据对待是正确的）
- **CCPA/CPRA**：加州客户的查询/删除/不出售权。1000 家店汇总的消费者数量很可能让**平台方**落入适用范围 → 必须内置 DSAR 流程和数据保留策略 ⭐
- **短信同意**：TCPA（见 1.8）
- **邮件**：CAN-SPAM，营销邮件必须有退订
- **支付**：平台不碰卡号、不连接终端、不代收业务款；现金或刷卡由店家在自己的渠道完成，系统只保存店家填写的金额记录
- **审计日志**：所有金额、小费、权限、客户数据的变更 append-only 留档

## 8. 终端形态与门店降级运行模式（核心：前台单端完全闭环）

针对亚裔实体店现实：**有的店没有 Kiosk，有的店老技师不用手机**。系统设计为**“前台单端完全闭环（Desk-Only Complete Mode）”**，Kiosk 和 Staff PWA 仅作为可选的效率增强端，绝非强依赖。

| 模式 | 适用门店 | 运行方式 |
|---|---|---|
| **模式 A：纯前台单端模式** ⭐<br>(Desk-Only) | 传统老店、老技师、无额外 iPad | **前台一屏包揽所有动作**：前台代客人签到/勾选同意书；大屏/口头喊号派单；前台代打卡；技师口头报加钟前台点加项；前台结账；打烊时展示现金小费表直接发现金。流程 100% 顺畅闭环，无任何等待技师确认的阻塞卡点。 |
| **模式 B：前台 + 墙面大屏**<br>(Desk + TV Turnboard) | 技师不带手机，但店里有公用电视/平板 | 技师抬头看墙上轮牌大屏（谁接下一单、哪个房间），前台负责开单结账。 |
| **模式 C：全数字化协同**<br>(Desk + Staff + Kiosk) | 年轻化/中大型沙龙 | 客人 Kiosk 自助签到，技师手机 PWA 实时接单，前台高效调度。 |

| 端 | 设备 | 使用者 | 核心与依赖性 |
|---|---|---|---|
| **Desk 前台端** | 桌面电脑 / 大平板 | 前台、店长、老板 | **P0 核心必须端**：具备全部全流程管理能力（包含所有代办模式），100% 独立闭环 |
| **Staff 员工端** | 手机 PWA / 共享 iPad | 技师 | **P1 可选增强端**：下一位客人 + 个人收入实时看板 + 快捷加钟（不用则由前台代办） |
| **Kiosk 客户端** | 门口 iPad | 客人 | **P2 可选增强端**：自助签到 + 电子免责书签字（不用则由前台代签或纸质打勾） |
| **Owner 老板端** | 手机 / 桌面 | 老板 | 内嵌于 Desk（高权限视图），支持手机远程看实时营业额与异常告警 |
